# task_1 수행계획서: Garage S3 및 Drive 공개 URL 연동

## 목표

TAD 웹 백엔드의 파일 업로드 대상을 Garage S3 호환 API로 전환하고, 공개 파일 URL을 Drive 서비스의 공개 경로로 일관되게 제공한다.

## 현재 현상 또는 요구사항

- 현재 저장 서비스는 객체 저장소 endpoint를 조합한 URL을 생성하여 데이터베이스에 저장한다.
- 분석 게임 데이터는 버킷과 객체 키를 이미 보관하지만, 게시판 첨부는 URL만 보관한다.
- 공개 파일은 Drive 서비스가 공개 버킷 정책을 확인한 뒤 제공해야 한다.

## 확인 방법

- 단위 테스트로 업로드 후 반환되는 버킷·객체 키·공개 URL을 확인한다.
- 데이터베이스 스키마와 운영 데이터를 확인한 뒤 마이그레이션을 적용한다.
- 전체 Gradle 테스트와 빌드를 실행한다.

## 원인 가설

저장소 endpoint와 사용자 공개 URL의 책임이 하나의 설정에 섞여 있어, MinIO에서 Garage 및 Drive 공개 경로로 전환할 때 이전 URL이 데이터에 남을 수 있다.

## 영향 범위

- S3 호환 저장소 설정 및 업로드 서비스
- 분석 이미지 응답
- 게시글·댓글 첨부 저장 및 응답
- `board`와 `analysis` 스키마
- 배포 환경 설정값

## 검증 방법

1. 관련 서비스 단위 테스트
2. 전체 Gradle 테스트
3. `bootJar` 빌드
4. 운영 DB의 변경 컬럼 및 기존 레코드 확인
5. GitHub Actions 배포 워크플로 트리거 확인

## 단계별 작업 개요

1. 저장소 설정과 공개 URL 생성 책임을 분리한다.
2. 게시판 첨부에 버킷·객체 키를 보관하도록 모델과 SQL 마이그레이션을 추가한다.
3. 기존 데이터를 안전하게 보완하고 테스트·빌드한다.
4. 변경을 `main`에 푸시한다.

## 승인

작업지시자의 코드 수정·DB 반영·`main` 푸시 지시로 승인되었다.
